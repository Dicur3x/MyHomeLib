Экспорт и импорт пользовательских данных

Команды «Коллекция» → «Экспорт» → «Данные пользователя» и «Коллекция» → «Импорт» → «Данные пользователя» (см. Меню «Коллекция») сохраняют в файл и возвращают обратно личные данные пользователя, привязанные к книгам активной коллекции, — отдельно от самого каталога книг.

Что попадает в файл

Экспорт берет только то, что касается активной коллекции:

  • для каждой книги с рейтингом, прогрессом чтения или рецензией (см. Рейтинг и статус «Прочитано») — эти три значения;
  • все группы из системной базы (в частности «Избранное» и «К прочтению» — см. Группы и избранное), а для каждой группы — те книги активной коллекции, которые в неё входят.

Файл сохраняется с расширением .mhlud2. Старую текстовую форму данных пользователя (расширение .mhlud, из предыдущих версий программы) импорт также понимает — распознает по расширению файла автоматически, отдельного действия для этого не требуется.

Как книги сопоставляются при импорте

Каждая запись в файле привязана к книге по стабильному идентификатору (LibID) — тому самому, по которому книги сопоставляются при обновлении коллекции (см. Обновление коллекции). Это работает и тогда, когда внутренние номера книг в коллекции уже другие, чем на момент экспорта, — например, после повторного импорта из INPX или полного обновления. Группы при импорте сопоставляются по названию: если группа с таким названием в системной базе уже есть (а «Избранное» и «К прочтению» есть всегда), книги добавляются именно в неё; если нет — создаётся новая.

Рейтинг и прогресс чтения импорт перезаписывает только тогда, когда значение из файла ненулевое, — и делает это безусловно (новым значением поверх существующего, независимо от того, больше оно или меньше текущего). Если же в файле для этих полей ноль (или значение отсутствует), существующие в коллекции рейтинг и прогресс остаются без изменений — обнулить их импортом данных пользователя нельзя.

Когда это нужно

Самое полезное — перед действиями, которые могут нарушить связь между книгами и этими данными: переустановкой программы, переносом коллекции на другой компьютер или полным реимпортом коллекции с нуля. Поскольку привязка идет по LibID, а не по внутреннему номеру книги, экспортированные данные корректно возвращаются обратно даже в заново созданную или полностью обновленную коллекцию — при условии, что книги в ней имеют те же LibID, что и раньше.

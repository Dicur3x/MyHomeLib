# План и журнал разработки MyHomeLib

Этот документ — единая точка продолжения работы над русской веткой MyHomeLib.
Он фиксирует не только идеи, но и уже принятые решения, незавершённые проверки и
условия выпуска. Новый разработчик или новый чат должен сначала прочитать этот
файл, затем `README.md` и `BUILDING.md`, и только после этого менять код.

## Постоянные требования проекта

- Русский — основной язык интерфейса и справки.
- При синхронизации с `upstream` все новые украинские пользовательские строки
  переводятся на русский. Русский текст нельзя заменять украинским.
- Заставка остаётся нейтральной, без украинского флага или жёлто-синей полосы.
- Изменения оригинального проекта переносятся «умным» слиянием: просматриваются
  все входящие коммиты, разрешаются смысловые конфликты, после чего выполняется
  сборка и регрессия.
- Обычные INPX/ZIP-коллекции обязаны работать как раньше.
- Поддерживаются Windows x64 и x86. Сначала проверяется x64, затем x86.
- В релиз попадает вся подготовленная папка `Bin64`/`Bin`, а не один EXE.
- RAD Studio после работы можно закрывать без сохранения автоматически
  изменённых `.dproj`, `.res` и `.dres`, если эти изменения не были внесены в
  исходники намеренно. Генерируемые ресурсы перед коммитом сверяются с `git
  status` и обычно восстанавливаются из `HEAD`.

## Как продолжить текущую работу

1. Убедиться, что открыто рабочее дерево
   `C:\Users\cloud\IdeaProjects\MyHomeLib-codex-worktree` и ветка
   `codex/flibrary-multiseries-compat-codex`.
2. Проверить `git log -2 --oneline` и `git status --short`. Реализация должна
   содержать коммит `956c8ef`; не уничтожать незнакомые изменения и не

3. Владелец требует два готовых ZIP с EXE, как и в предыдущих релизах.
4. Попросить владельца явно проверить уже запущенную Win64-сборку: подпись

   обрезаться.
5. В Delphi 13 открыть
   `Program\MyhomeLib.dproj`, выбрать `Release` и нужную платформу, затем
   выполнить **Project → Build MyHomeLib**. Аналогично собрать
   `Utils\MHLMcpServer\MHLMcpServer.dproj`. Для продолжения в первую очередь
   нужны свежие `Windows 32-bit` версии обоих проектов. DLL значков Win32 можно
   использовать существующую только после проверки разрядности и ресурсов.
6. Подготовить комплектные инструменты для обеих архитектур:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\prepare-flibrary-runtime.ps1 -Platform Win64
   powershell -ExecutionPolicy Bypass -File .\scripts\prepare-flibrary-runtime.ps1 -Platform Win32
   ```

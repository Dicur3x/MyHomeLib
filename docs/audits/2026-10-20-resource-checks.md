# Проверка ресурсов перед pre5.26

Повторные отказы общего счётчика USER удалось связать с контекстами ввода,
созданными для живых служебных потоков Windows. Это уточнение проверки,
а не исправление обнаруженной утечки в коде приложения.

В неудачном Win32-проходе счётчик вырос с 151 до 157 одновременно с ростом
числа HIMC с 13 до 19. В Win64 — с 148 до 155 и с 10 до 17 соответственно.
Во всех этих точках сохранялись те же 51 HWND и 32 созданных VCL-контрола
главного окна; оставшихся форм читалки не было. Дополнительная инвентаризация
живых потоков показала служебные потоки с точкой входа в `ntdll.dll`.
Windows по умолчанию создаёт контекст ввода для каждого потока:
[описание IMM](https://learn.microsoft.com/en-us/windows/win32/intl/input-context).

Проверка теперь отдельно учитывает ровно один HIMC на живом служебном потоке,
если его точка входа принадлежит `ntdll.dll`. Основной UI-поток, потоки из EXE,
дополнительные контексты, окна, меню, значки и остальные USER-объекты остаются
в проверяемом счётчике. Если определить происхождение потока невозможно,
исключение к нему не применяется. Исходный общий счётчик также выводится
в журнал, поэтому результаты до и после уточнения не смешиваются.

Допуск для ресурсов приложения остаётся +4 USER и +4 GDI после каждого
закрытия. Точное сравнение состава и свойств HWND/VCL-контролов, отсутствие
читалки среди форм, видимость и доступность главного окна и хеши входных
файлов проверяются независимо от числового допуска. После двух отдельно
отчётных первых открытий выполняются 8 исходных и ещё 24 стрессовых цикла
ошибки/отмены. Увеличения допуска или дополнительного прогрева до получения
успешного результата нет.

Окончательные проходы с этим учётом:

| Архитектура | Циклы | USER приложения: база → конец | GDI: база → конец | HWND / VCL |
|---|---:|---:|---:|---:|
| Win32 | 32 | 142 → 142 | 443 → 443 | 51 / 32, без изменений |
| Win64 | 32 | 143 → 141 | 441 → 441 | 51 / 32, без изменений |

Win32: тестовый EXE SHA-256
`32c9c91fe5acc778c9c9459486ffc8a04eca89bf57ae2b7352e003468d403a29`.
Win64:
`b4182332ccf30a06e0fa440648f553dc36fb4f1fc78afb60cdbadaf2a3dfe165`.
Оба собраны в Delphi GUI / Performance из обычного проекта проверок.

В программу не включались отключение IME, диагностические перехваты API
или изменение работы читалки ради счётчика. Полные журналы, исходные отказы
и снимок происхождения потоков сохранены в локальном каталоге
`tools/ui/tests/Out/post525-audit`; краткие результаты входят в итоговый отчёт.

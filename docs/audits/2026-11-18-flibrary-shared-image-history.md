# Выборочное сжатие общих изображений FLibrary

При выборе одной книги из двух с одинаковым именем в разных папках одного
7z прежний обработчик оставлял общую иллюстрацию на месте, но отмечал книгу
в истории как полностью проверенную. Это воспроизведено через обычный запрос
подготовки. В исправленном варианте отчёт для пользователя и запись для каталога
согласованы. Если в архиве изображений нет обложки или иллюстрации с таким
именем владельца, совпадение имён самих книг не мешает завершить проверку.

| Проверка | Результат |
| --- | --- |
| Исходный 7z с шестью файлами, отдельные ZIP с обложками и иллюстрациями | При частичном выборе две записи с общей картинкой остались открыты для досжатия. Третья, без общей картинки, завершилась. При совместном выборе обработчик принял все шесть записей. Исходные три архива сохранили контрольные суммы. |
| Повторная подготовка с реальным кодировщиком, прежние имена архива и двух иллюстраций | Одна иллюстрация заменена при обновлении тестовых данных. Обработчик снова сжал её и сохранил байты ранее обработанной соседней картинки. |
| Сохранение результата в SQLite на x86 и x64 | Два сценария на каждой архитектуре. Проверены повтор после неполной проверки, сохранение истории другого режима и пропуск незавершённой соседней книги при замене архива. Для x86 использована SQLite из кандидата дистрибутива. |

Тесты подготовки находятся в `test_prepare_book_compression.py` и
`test_external_image_preparation.py`, тесты записи в каталог — в
`test_native_compression_receipt.py`. Результаты запуска сохранены в
`r1985-shared-flibrary-history`. Отдельный запуск x86 без комплектной SQLite
остановился на неподдерживаемом синтаксисе SQL. Повтор с DLL из `HomeLibre.zip`
прошёл оба сценария.

Проверка замены картинки относится к книге, которая уже попала в обработку.
Автоматический отбор по быстрым признакам файла имеет отдельные проверки.
Перед выпуском требуется собрать обновлённый модуль обработки книг и проверить
сценарий из пользовательской команды в составе окончательной поставки.


### Сравнение иллюстраций перед сжатием, 19 ноября

В выборке для окна сравнения проверены FB2 с WebP и EPUB с изображениями
WebP и двухстраничным TIFF. Для одного ресурса имя не имело расширения.
Содержимое обеих сторон сравнили побайтно с соответствующими ресурсами книг.
Затем настоящее окно открыло три пары. Проверены размеры 23 × 17 и цвет
известного пикселя с каждой стороны, включая первую страницу TIFF.

Для EPUB, вложенного в общий 7z в виде отдельного 7z, проверка извлекла
обработанную книгу из подготовленного архива и сверила её иллюстрацию с той,
которую показывает сравнение. Исходный архив, соседняя книга и текст EPUB
прошли отдельные проверки.

На x86 и x64 прошли по 11 сценариев. Главные приложения собраны для обеих
архитектур. Упакованные модули BookProcessing открыли контрольные WebP и TIFF
своими комплектными Python и сохранили обе стороны сравнения побайтно.
Журналы находятся в `r1990-raster-comparison`. Сквозное обновление beta 13
с этими изменениями предстоит повторить на окончательной поставке.


Дополнительно проверен полный путь от выбора трёх книг до подготовки архива.
Для FB2 и обычного EPUB исходная версия модуля обработала WebP. Для EPUB с
картинкой без расширения проверка ошибочно отклонила результат. Исправлена
сверка ресурсов с описанием EPUB и поиск изображений внутри вложенного 7z.
Контрольный цветной WebP был переведён в оттенки серого в трёх книгах.
Проверены все пиксели результата, исходные и подготовленные байты в окне
сравнения и содержимое соседнего файла. Отдельный тест проверяет, что замена
необъявленного растровым вложения без расширения всё ещё отклоняется.
Для вложенной FLibrary EPUB результат извлечён из обоих уровней 7z.
Три задания запущены через официальную точку входа упакованных обработчиков
x86 и x64 на синтетических книгах. Итоги и размеры содержатся в
`r1991-djvu-quality/sealed2-Win32.log` и `sealed2-Win64.log`.

# Как собрать HomeLib Ru в `exe`

Инструкция рассчитана на человека, который не пишет на Delphi. Ниже описан
реально проверенный путь для **RAD Studio / Delphi 13 Trial**, конфигурации
**Release** и платформ **Windows 32-bit и Windows 64-bit**.

Состояние на 6 октября 2026 года: опубликованная поставка
**pre5.09 / 1076**, ZIP в `Installer\Out\pre5.09-publish`. Разделы предыдущих
выпусков сохраняют результаты на дату своей проверки; не считать их новыми
прогонами. Рабочее дерево и правила продолжения: [NEXT_CHAT_PROMPT.md](NEXT_CHAT_PROMPT.md).
Delphi 13.2 Trial `37.0.60952.8797` используется для текущих обычных сборок
Win32/Win64. Сведения ниже о pre5.07 относятся к проверкам 1 октября.

## Проверка pre5.10 / 1077: очистка копий для чтения

Подготовлен новый выпуск **pre5.10 / 1077**, обычные Win32/Win64.
Исправление касается временного кэша `webp-png`: прежний `ClearDir`
удалял только файлы непосредственно в папке и пропускал этот кэш.
Команда «Инструменты → Очистить папку “Для чтения”» очищает его вместе
с обычными файлами выбранной папки. При выходе очищается временная папка
после завершения фоновой очереди. Отдельная постоянная папка для чтения
сохраняется при выходе; исходные книги и архивы сохраняются.

Новая функция не обходит посторонние подпапки и не следует по junction.
Если читалка заняла файл, очистка продолжает удалять доступные файлы;
занятая копия остаётся до следующей очистки.

Полные сборки группы проектов через Delphi 13.2 Trial завершены без ошибок:
Win32 — 0 предупреждений, Win64 — прежние 6 W1029. Главные EXE имеют
FileVersion **2.7.0.1077**, обе программы — ProductVersion **2.7.0_pre5.10**;
FileVersion MCP остаётся **1.0.0.0**.

6 октября на свежих нативных EXE обеих архитектур прошли:

- Реестр жанров, **11 групп импорта/экспорта**, **10 локальных сценариев
  главной формы** и **2 онлайн-сценария**. Новые сценарии вызывают настоящую
  команду очистки и разрушение главной формы: копии удаляются, занятый файл
  сохраняется и удаляется после освобождения, исходная книга и постоянная
  папка при выходе сохраняются. Посторонняя подпапка и цель junction остаются.
- Сетевой MCP `download_tests.js`: **7/7 PASS**, включая онлайн-ZIP,
  перенаправление POST → GET, извлечение книги, точные байты и сообщения VCL.

  всех **224 файлов справки** в обеих поставках. Раздел о чтении дополнен

Проверки выполнялись только во временных профилях, без личной библиотеки.

## Проверка pre5.09 / 1076: онлайн-загрузка

До исправлений проверен исходный код опубликованного pre5.08:

- Прежние пять сценариев `download_tests.js` прошли на опубликованных
  MCP Win32 и Win64. Расширенный нативный Win32-тест прошёл семь сценариев:
  настоящий онлайн-ZIP с Deflate, POST → 303 → GET `%RESURL%`, несовпадающее
  имя FB2 внутри ZIP, точные байты загрузки, извлечение книги и метаданных,
  локальные отметки и сообщения VCL. WebP включён по умолчанию; обычный FB2
  без WebP сохранил исходные байты.
- Настоящая главная форма Win32 скачала стандартный онлайн-ZIP при открытии
  книги, обновила локальный статус, показала обложку и открыла подготовленный
  FB2. При старте очереди воспроизведён `EThread: Cannot call Start on a
  running or suspended thread`. Отдельный онлайн-FB2 воспроизвёл чтение
  отсутствующего файла до первого HTTP-запроса.
- Причина ошибки запуска очереди подтверждена чтением машинного кода
  установленного RTL Delphi 13.2 Trial `37.0.60952.8797`: `Start` внутри
  конструктора сбрасывает признак первоначальной приостановки, после чего
  `AfterConstruction` повторно вызывает `ResumeThread` и получает ошибку.
  Использованы поставляемые `rtl370.map`/`rtl370.bpl` обеих разрядностей;
  тот же код найден в статически связанном опубликованном EXE Win64 1075
  и проверочном EXE Win32. Запуск после конструктора описан также в
  [официальной документации AfterConstruction](https://docwiki.embarcadero.com/Libraries/Sydney/en/System.Classes.TThread.AfterConstruction).
  Системные файлы не менялись.

Исправление переносит запуск очереди за завершённый конструктор, скачивает
отдельный онлайн-FB2 до подготовки WebP, восстанавливает режим выбора книг
через `finally` и отклоняет объединённый INPX в онлайн-коллекции до изменения
данных и параметров подключения. При отказе импорта транзакция откатывается.

- Из исходников проект собирается только компилятором Delphi с VCL. Free Pascal
  и обычный Visual Studio для этого проекта не подходят.
- В Trial-версии командная сборка отключена, поэтому проекты нужно собирать в
  окне Delphi. Это ограничение лицензии Trial, а не ошибка проекта.
- Не открывайте `Program\MHL.groupproj` в Trial: в проверенной Delphi 13 Trial
  проверка зависимостей группы завершалась сбоем IDE. Три нужных проекта
  надёжнее собрать по одному, как описано ниже.
- Если RAD Studio нет, самый простой вариант — получить у разработчика уже
  собранную папку `Bin64` целиком. Один `HomeLibRu.exe` без соседних файлов —
  неполная поставка.

## Что получится

Готовая 64-битная папка находится в `Program\Out\Bin64`. Для полноценной
поставки в ней должны быть:

- `HomeLibRu.exe` — основная программа;
- `sqlite3.dll` — движок базы данных той же разрядности;
- `libzstd.dll` — распаковка каталогов нового формата metabib;
- `tools\7zip\7za.exe` — чтение книг из компактных раздач FLibrary;
- `tools\jpeg-xl\djxl.exe` — преобразование вынесенных JPEG XL-иллюстраций в
  обычный JPEG/PNG;
- `Readers\AlReader\AlReader2.exe` — чтение FB2/FBD, DOC/DOCX, RTF, TXT и
  HTML;
- `Readers\SumatraPDF\SumatraPDF.exe` — свободная переносимая читалка для PDF,
  DjVu, EPUB, MOBI/Kindle, CHM, XPS, комиксов и графических форматов; рядом с
  ней находятся тексты лицензий и список авторов;
- `MHLMcpServer.exe` — вспомогательный MCP-сервер;
- `Icons\MHLIcons.dll` — значки интерфейса;
- каталог `Help` — встроенная справка;
- файлы `genres_*.glst` — штатные списки жанров.
- `HomeLibRu.url` — ссылка на репозиторий этой ветки, добавляемая при упаковке;
- `LICENSE` и `NOTICE` — неизменные уведомления оригинального проекта.

Для Win32 аналогичная папка называется `Program\Out\Bin`. Сначала обычно
собирают Win64, а затем повторяют те же шаги с платформой Windows 32-bit.

## 1. Один раз установите зависимости

1. Установите **RAD Studio 13 / Delphi 13 (Studio 37.0)**. В установщике должны
   быть отмечены Delphi, VCL и платформа Windows 64-bit.
2. В Delphi откройте **Tools → GetIt Package Manager**, найдите
   **Virtual Treeview (Latest Version)** и установите пакет. В проверенной
   сборке использовалась версия 8.3. После установки перезапустите Delphi.
3. Компоненты Konopka/Raize (`BonusKSVC`, `RzPanel` и подобные) больше не нужны:
   проект переведён на стандартные компоненты VCL.
4. Скачайте с [официальной страницы SQLite](https://www.sqlite.org/download.html)
   архив `sqlite-dll-win-x64-...zip` и распакуйте `sqlite3.dll` в удобную
   временную папку. Для Win32 нужен архив `sqlite-dll-win-x86-...zip`.
5. Node.js нужен для пересоздания встроенных переводов и запуска тестовых
   сценариев. При его отсутствии сборочный сценарий сохраняет существующий
   языковой ресурс либо создаёт пустой; русские строки всё равно входят в EXE
   из исходников. Приватный ключ для штатных встроенных каталогов этой ветки
   не требуется. Политика upstream с обязательной подписью таких каталогов
   намеренно не перенесена.

## 2. Соберите три проекта в Delphi Trial

Каждый раз используйте **File → Open Project**, затем в правой панели проверьте:

- **Build Configurations: Release**;
- **Target Platforms: Windows 64-bit** (либо **Windows 32-bit** для второй
  сборки).

Для сборки текущего проекта используйте **Project → Build <имя проекта>**
(штатная клавиша — **Shift+F9**). После открытия справа должно быть написано
`MyhomeLib.dproj - Projects`, а не `MHLComponents.dproj - Projects`: название
окна редактора само по себе не переключает активный проект. После успешной
сборки Delphi показывает окно `Success`; предупреждения допустимы, но `Errors`
должно быть 0.

**Ctrl+Shift+F9 не является Build:** это запуск без отладчика. Для сборки
используйте именно Shift+F9 или пункт меню Project. После внешнего изменения
исходников перечитайте открытые файлы с диска, чтобы IDE не собрала старый
буфер. Уже существовавшие локальные изменения `.dpr`/`.dproj` сохраняйте;
не откатывайте их ради чистого статуса и не коммитьте автоматически.

Соберите проекты в таком порядке:

1. `Program\Resources\Icons\MHLIcons.dproj` — создаёт
   `Program\Resources\Icons\Win64\MHLIcons.dll`.
2. `Program\MyhomeLib.dproj` — создаёт `Program\Out\Bin64\HomeLibRu.exe` и
   автоматически копирует рядом каталоги `Help`, `Icons` и нужную
   `libzstd.dll`.
3. `Utils\MHLMcpServer\MHLMcpServer.dproj` — создаёт
   `Program\Out\Bin64\MHLMcpServer.exe`.

После каждого проекта его можно закрыть и на вопрос о сохранении автоматически
изменённых файлов ответить **No**. Пользовательские настройки IDE для сборки не
нужны.

Для Win32 повторите этот порядок, выбрав **Windows 32-bit**. Результаты будут
находиться в `Program\Resources\Icons\Win32` и `Program\Out\Bin`.

Пакет `Components\MHLComponents\MHLComponents.dproj` для обычного EXE собирать
не требуется: используемые программой модули компонентов подключены к EXE
напрямую. Пакет нужен только разработчику, который хочет устанавливать эти
компоненты в палитру дизайнера форм.

## 3. Добавьте SQLite и проверьте всю папку

Сначала подготовьте два небольших свободно распространяемых инструмента для
поддержки раздач FLibrary:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-flibrary-runtime.ps1 `
  -Platform Win64
```

Сценарий загружает официальные 7-Zip 26.02 и JPEG XL 0.12.0, проверяет их
закреплённые SHA-256, кладёт только нужные исполняемые файлы и лицензии в
`Program\Out\Bin64\tools`. Если там уже находится другая версия, сценарий не
перезапишет её без явного `-Force`. Для Win32 замените платформу на `Win32`.
Сценарий выбирает официальный статический `djxl.exe` нужной архитектуры: x64
для Win64 и x86 для Win32. Поэтому восстановление JPEG XL работает и в
32-разрядной поставке на 32-битной Windows.

Теперь подготовьте комплектные программы для чтения. AlReader берётся из уже
имеющейся переносимой папки, а официальный SumatraPDF 3.6.1, тексты лицензий
и список авторов
скачиваются сценарием с проверкой закреплённых SHA-256:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-readers.ps1 `
  -Platform Win64 `
  -AlReaderDirectory "C:\Portable\AlReader"
```

Для второй сборки замените платформу на `Win32`. Сценарий создаёт единообразную
структуру `Readers\AlReader` и `Readers\SumatraPDF`; если AlReader уже лежит в
старой папке `Bin64\AlReader`/`Bin\AlReader`, параметр
`-AlReaderDirectory` можно не указывать.

После этого проверьте остальные файлы поставки.

Откройте PowerShell в корне репозитория. Сначала запустите безопасную проверку,
подставив свой путь к распакованной DLL:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 `
  -Platform Win64 `
  -SqliteDll "C:\Downloads\sqlite3.dll"
```

Если проверка прошла, повторите команду с `-Copy`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 `
  -Platform Win64 `
  -SqliteDll "C:\Downloads\sqlite3.dll" `
  -Copy
```

При повторной сборке в папке `Bin`/`Bin64` могут остаться старые копии SQLite
или списков жанров. Чтобы явно заменить только проверяемые сценарием файлы их
актуальными версиями, добавьте `-Force`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 `
  -Platform Win64 `
  -SqliteDll "C:\Downloads\sqlite3.dll" `
  -Copy `
  -Force
```

Сценарий проверяет разрядность EXE, SQLite, zstd, MCP-сервера и DLL значков,
наличие обеих читалок, справку и лицензии, копирует списки жанров и выводит
SHA-256 основных файлов. Он не перезаписывает уже существующий отличающийся
файл без явных `-Copy -Force`.

Для текущего выпуска он ожидает `HomeLibRu.exe` версии `2.7.0.1068` и
проверяет название продукта и встроенный манифест. Ключ `-Copy` также
размещает рядом точные `LICENSE` и `NOTICE` из корня репозитория;
`-Copy -Force` заменяет их только при явном повторном запуске.

Теперь запустите:

```text
Program\Out\Bin64\HomeLibRu.exe
```

При первом запуске должно появиться русское окно «Мастер создания коллекции».
Для переноса на другой компьютер копируйте всю папку `Bin64`, а не только EXE.

Для проверки поведения большой коллекции откройте вкладку «Жанры» и выберите
верхнюю группу, например «Фантастика». Она не должна сама раскрываться или
загружать книги. Кнопка «Показать» справа от названия жанра должна по явному
щелчку загрузить книги этой группы и всех её поджанров; выбор обычного поджанра
по-прежнему загружает только его книги.

Необязательная встроенная проверка MCP-сервера запускается так:

```powershell
.\Program\Out\Bin64\MHLMcpServer.exe --cache-selftest
```

Успешный результат завершается кодом 0 и содержит `"pass":true` для всех
проверок.

Разработчик может воспроизвести восстановление одной книги FLibrary без
создания или изменения коллекции:

```powershell
.\Program\Out\Bin64\MHLMcpServer.exe --restore-flibrary `
  "D:\Collection\d.usr-000001-001000.7z" `
  "Book.epub" `
  "$env:TEMP\restored.epub"
```

При успехе команда завершается кодом 0, выводит `"restored":true`, наличие и
размер обложки, а также время этапов `cover_ms`/`extract_ms`/`restore_ms`, затем
создаёт обычный FB2/EPUB по указанному третьему пути. `cover_ms` отдельно
проверяет быстрый путь панели сведений, который не пересобирает всю книгу.

## 4. Сборка из командной строки

В установленной Trial-версии этот способ **не работает**: компилятор выводит
`This version of the product does not support command line compiling`. У Trial
нет финальных консольных компиляторов — это также описано в
[справке Embarcadero](https://docwiki.embarcadero.com/Support/en/%E2%80%9CThis_version_of_the_product_does_not_support_command_line_compiling%E2%80%9D_with_a_valid_Delphi_10.1_Berlin_license).

Полностью собрать этот проект вообще без Delphi нельзя: он использует
компилятор Delphi и библиотеку VCL. В полной лицензии Delphi можно не открывать
тяжёлую IDE, а запустить **RAD Studio Command Prompt** и собрать проекты
по отдельности:

```bat
msbuild Program\Resources\Icons\MHLIcons.dproj /t:Build /p:Config=Release /p:Platform=Win64 /nologo /v:minimal
msbuild Program\MyhomeLib.dproj /t:Build /p:Config=Release /p:Platform=Win64 /nologo /v:minimal
msbuild Utils\MHLMcpServer\MHLMcpServer.dproj /t:Build /p:Config=Release /p:Platform=Win64 /nologo /v:minimal
```

Обычный терминал может не содержать переменные и пути Delphi, поэтому для
этого варианта нужен именно RAD Studio Command Prompt.

## 5. Как получить установщик

Для собственного использования достаточно проверенной папки `Bin64`. Если
нужен установщик:

1. Установите [Inno Setup 6](https://jrsoftware.org/isinfo.php).
2. Сначала полностью подготовьте папку `Bin64`, как описано выше.
3. Из корня проекта выполните `Installer\build_installer.cmd x64`.

Варианты команды: `x86`, `x64` или `all`. Результат появляется в
`Installer\Out`.

На 1 октября в обоих `Setup_Script_MyHomeLib*.iss` осталось
`ReleaseVersion = '2.7.0_pre5.02'`. Перед будущим выпуском установщика нужно
согласовать это значение с новой версией. Не собирать текущий runtime 1073
под старым именем и не считать ISS готовыми установщиками pre5.06.

`Installer/LegacyUpgrade.iss` удаляет старый `MyHomeLib.exe` только после
установки нового EXE, если прежняя запись удаления с тем же AppID указывает
ровно на текущую папку установки. Старые ярлыки удаляются только при
подтверждённой ссылке на этот старый EXE. Профили, коллекции и общие файлы не
затрагиваются. Отдельный `Installer/tests/LegacyUpgradeCompile.iss`
предназначен только для проверки компиляции, запускать его нельзя. На этой
машине при предыдущей проверке ISCC отсутствовал; компиляция и реальное
обновление установщиком не проверены. pre5.06 опубликован в виде двух ZIP,
без установщика.

## 6. Как подготовить архивы релиза

После свежей сборки, регрессии и подготовки обеих папок runtime выберите
новый, ещё не использованный каталог (ниже пример, не команда повторной
публикации pre5.06). Сначала согласуйте новую версию в проектах, манифесте,
`scripts/prepare-runtime.ps1`, `scripts/package-release.ps1` и
`update/last_version.info`:

```powershell
.\scripts\package-release.ps1 -Platform Win32 -OutputDirectory .\Installer\Out\next-release-publish
.\scripts\package-release.ps1 -Platform Win64 -OutputDirectory .\Installer\Out\next-release-publish
```

Сценарий повторно запускает проверку runtime и создаёт
`HomeLibRu.zip` и `HomeLibRu_x64.zip` в выбранном каталоге. Он берёт перечисленные
файлы и штатные каталоги поставки, а не всю папку запуска. Перед упаковкой
убедитесь, что в `Readers`, `Help`, `Icons` и `tools` не попали личные файлы
или настройки от проверочных запусков. Пустой штатный маркер AlReader
`$savevtut.ini` является частью portable-комплекта.

Существующий архив не перезаписывается. Для повторной упаковки задайте
отдельную папку параметром `-OutputDirectory`. `LICENSE` и `NOTICE`
включаются без изменений. Каталог `pre5.02-final` содержит отбракованный
кандидат с рабочими файлами читалки, его публиковать нельзя. Актуальные
архивы 1073 и их SHA-256 перечислены в верхнем разделе этого документа.

### Историческая упаковка pre5.01

Финальные архивы pre5.01 в `pre5-final` были созданы и проверены:

| Архив | Размер, байт | SHA-256 |
| --- | ---: | --- |
| `HomeLibRu.zip` | 23932852 | `0DFC91A18DB7CDF6EB7C3E061BBBC3A521512C197ACD10D9BF83B0FE3978FDAB` |
| `HomeLibRu_x64.zip` | 26798475 | `0476A0B5EA788F0627059A24C1CE5210547DC7853112D8BB42FA29AB930DD33D` |

В ZIP проверены 272 записи Win32 и 280 записей Win64: содержимое совпало

текущим исходникам. Эти архивы опубликованы в

для публикации их использовать нельзя. Параметр `-OutputDirectory`
позволяет отделять итоговую поставку от кандидатов.

### Обновление и откат ZIP-поставки

ZIP распаковывайте в чистую папку, не поверх старой версии. Перед переходом
закройте обе программы и сохраните резервную копию `%APPDATA%\MyHomeLib`
и отдельных `.hlc2`. Обычный профиль по-прежнему имеет имя MyHomeLib и
используется новой программой без переименования. Для portable-профиля
перенесите из резервной копии собственный `myhomelib2.ini`, папку `Data`
и `presets.cxml2`; рядом с EXE должен быть пустой маркер `uselocaldata` без
расширения (либо такой параметр запуска). Один INI рядом с EXE portable-режим
не включает. Затем проверьте пути к коллекциям. Упаковка и распаковка ZIP
не удаляют старые EXE, профили или пользовательские файлы автоматически.

Возврат к старому EXE выполняется только с отдельной резервной копией профиля
и коллекций, сделанной до обновления. Старые версии не обслуживают таблицы
издательских серий: полное пересоздание каталога старой программой может
оставить связи по BookID от прежних книг. Не используйте старую и новую
версии по очереди для изменения одной рабочей `.hlc2`.

## Частые ошибки

### Не найден `VirtualTrees`, `VirtualTreesD` или `VirtualTreesR`

Virtual Treeview не установлен для Delphi 13 либо Delphi не была перезапущена
после GetIt. Установите пакет заново и не используйте готовые DCU/BPL от другой
версии Delphi.

### Delphi Trial падает при открытии или сборке группы

Не используйте `Program\MHL.groupproj`. Закройте Delphi и соберите три `.dproj`
по отдельности в порядке из раздела 2.

### Ошибка завершающего шага `copy_help`, `copy_icons` или `post_build`

Проверьте, что проект значков был собран первым и существует файл
`Program\Resources\Icons\Win64\MHLIcons.dll`. Для копирования справки также
нужен штатный `C:\Windows\System32\robocopy.exe`.

### Программа сообщает, что не найдена `sqlite3.dll`

DLL не скопирована рядом с `HomeLibRu.exe` либо имеет другую разрядность.
Повторите раздел 3 и используйте именно x64-DLL для Win64.

### Импорт metabib сообщает, что не найдена `libzstd.dll`

Сначала снова соберите `Program\MyhomeLib.dproj`: завершающий шаг копирует
`Program\Resources\zstd\Win32` или `Win64\libzstd.dll` рядом с EXE. Не
копируйте DLL другой разрядности — `prepare-runtime.ps1` это обнаружит.

### Не открывается книга из архива 7z

Запустите `scripts\prepare-flibrary-runtime.ps1` для нужной платформы и
проверьте наличие `tools\7zip\7za.exe` рядом с программой. Установленный в
системе 7-Zip также распознаётся, но для переносимой поставки рекомендуется
штатная папка `tools`.

### Книга открылась без вынесенных иллюстраций

Проверьте, что рядом с корневыми архивами раздачи скачаны соответствующие ZIP
в папках `covers` и `images`, а рядом с программой есть
`tools\jpeg-xl\djxl.exe`. Незавершённый боковой архив намеренно пропускается:
программа позволяет читать текст, пока торрент продолжает загружаться.

### Программа запускается без иконок

Убедитесь, что рядом с EXE есть `Icons\MHLIcons.dll`, а затем повторно соберите
`Program\MyhomeLib.dproj`, чтобы его завершающий шаг скопировал актуальную DLL.

Если при запуске появляется сообщение о ресурсе вроде
`LIGHT_FILETYPE_FILETYPE_FB2`, DLL значков устарела. Снова соберите сначала
`Program\Resources\Icons\MHLIcons.dproj`, затем `Program\MyhomeLib.dproj`.
Файлы `Program\Resources\Icons\Win64\MHLIcons.dll` и
`Program\Out\Bin64\Icons\MHLIcons.dll` после этого должны совпадать.

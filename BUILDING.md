# Сборка MyHomeLib для Windows

Эта инструкция рассчитана на человека, который раньше не работал с Delphi.
Самый надёжный путь — собрать приложение в графической среде Delphi и затем
положить рядом с ним подходящую `sqlite3.dll`.

## 1. Что понадобится

1. **[Delphi 12 Community Edition](https://www.embarcadero.com/products/delphi/starter)**
   либо лицензированная Delphi 13 с поддержкой VCL и целевых платформ Windows
   32-bit и Windows 64-bit. На июль 2026 года бесплатная Community Edition на
   официальной странице — именно версия 12. Если нужной платформы нет в списке,
   добавьте её через установщик/Feature Manager Delphi.
2. **[Virtual TreeView](https://github.com/JAM-Software/Virtual-TreeView)** для той же версии Delphi:
   откройте **Tools → GetIt Package Manager**, найдите `Virtual TreeView` и
   нажмите **Install**. После установки перезапустите Delphi.
3. Исходники MyHomeLib в обычной папке, в которую у пользователя есть право
   записи. В пути допустимы пробелы.
4. Официальная сборка `sqlite3.dll` нужной архитектуры со
   [страницы загрузки SQLite](https://www.sqlite.org/download.html). DLL не
   хранится в этом репозитории и не скачивается скриптами автоматически.

FastMM5 для обычной сборки **не нужен**. Компоненты MyHomeLib уже подключены к
проекту относительным путём, поэтому добавлять локальные `C:\Users\...` пути в
настройки Delphi не требуется.

## 2. Сборка `exe` в Delphi Community Edition

1. Запустите Delphi.
2. Выберите **File → Open Project** и откройте
   `Program\MyhomeLib.dproj`.
   Не используйте `Program\MHL.groupproj` для первой сборки: в него также входит
   design-time пакет компонентов, который для получения `exe` не нужен.
3. В верхней панели выберите конфигурацию **Release**.
4. Выберите целевую платформу:
   - **32-bit Windows / Win32** — наиболее совместимый вариант;
   - **64-bit Windows / Win64** — вариант для 64-битной Windows.
5. Выполните **Project → Build MyhomeLib**.
6. Проверьте результат:
   - Win32: `Program\Out\Bin\MyHomeLib.exe`;
   - Win64: `Program\Out\Bin64\MyHomeLib.exe`.

Конфигурация Release включает оптимизацию и inlining и не подключает debug DCU
или принудительные stack frames. Конфигурация Debug оставлена диагностической:
она медленнее, но удобнее для поиска ошибок.

### Если Delphi сообщает, что не найден `VirtualTrees`

Virtual TreeView либо не установлен, либо установлен для другой версии Delphi.
Повторите установку через GetIt именно в той Delphi, которой открыт проект.
Добавлять случайно найденные DCU/BPL от другой версии нельзя: формат этих файлов
зависит от версии компилятора и архитектуры.

### Если Delphi сообщает, что не найден `FastMM5`

В актуальном проекте FastMM5 отключён по умолчанию. Убедитесь, что в
**Project Options → Delphi Compiler → Conditional defines** нет символа
`USE_FASTMM5`. После удаления символа выполните **Build**, а не только Compile.

### Пакет `MHLComponents`

Для компиляции `MyHomeLib.exe` устанавливать пакет не нужно: его исходники
компилируются вместе с приложением. Пакет требуется только для работы с этими
компонентами в визуальном дизайнере форм. В этом случае сначала установите
Virtual TreeView, затем откройте
`Components\MHLComponents\MHLComponents.dproj`, соберите его для платформы IDE
и используйте **Component → Install Packages**. Собранный BPL находится в
`Components\MHLComponents\Out\Bpl\<платформа>`. Проект учитывает разные имена
пакетов Virtual TreeView в Delphi 12 и 13, но устанавливать BPL всё равно нужно
средствами той же версии IDE, а не копировать пакет от другой Delphi вручную.

## 3. Подготовка папки запуска

Минимум для старта программы:

- `MyHomeLib.exe`;
- `sqlite3.dll` **той же архитектуры**, что и `exe`.

SQLite подключён статическим импортом по имени `sqlite3.dll`, поэтому без него
Windows не запустит приложение. Нельзя класть 64-битную DLL рядом с Win32 `exe`
или наоборот.

Для обычного запуска списки жанров не нужны, но для создания новой коллекции
нужен подходящий `genres_fb2.glst` или `genres_nonfb2.glst`. Положите штатные
файлы рядом с `exe` либо явно выберите собственный совместимый `.glst` в
мастере. Эти файлы относятся к дистрибутиву данных и в чистом клоне репозитория
отсутствуют. `MyHomeLib.chm`, каталог `AlReader` и
каталог `converters` необязательны: без них не будут доступны соответственно
локальная справка, встроенный ридер и отдельные операции конвертации.

### Безопасная проверка и копирование DLL

Скрипт `scripts\prepare-runtime.ps1` ничего не загружает из интернета. Он:

- проверяет архитектуру `exe` и DLL по заголовку PE;
- не заменяет уже существующий файл с другим SHA-256;
- копирует только при явном параметре `-Copy`;
- печатает SHA-256 подготовленных файлов.

Проверить уже подготовленную Win32-папку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 -Platform Win32
```

Проверить указанную DLL, но пока не копировать её:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 -Platform Win64 -SqliteDll "C:\Downloads\sqlite3.dll"
```

Проверить и скопировать DLL рядом с `exe`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 -Platform Win64 -SqliteDll "C:\Downloads\sqlite3.dll" -Copy
```

Если файл назначения уже существует и отличается, скрипт завершится ошибкой.
Сначала самостоятельно сохраните старый файл под другим именем или удалите его,
если уверены, что он больше не нужен.

## 4. HTTPS и OpenSSL

Сетевой код использует Indy с историческим интерфейсом OpenSSL. DLL загружаются
динамически, поэтому приложение может запуститься без них, но HTTPS-загрузка и
проверка обновлений могут не работать.

Ожидаемые имена файлов:

- `libeay32.dll`;
- `ssleay32.dll`.

Суффикс `32` является частью старого имени и **не означает**, что эти файлы
подойдут для Win64: для Win64 всё равно нужны 64-битные сборки с теми же именами.
Эта ветка Indy рассчитана на устаревший API OpenSSL 1.0.x. Не скачивайте DLL с
случайных сайтов и учитывайте ограничения безопасности старой версии. Переход
на OpenSSL 3 или системный TLS Windows требует отдельного изменения сетевого
кода, а не простой замены файлов.

> Важно: текущая связка Indy/OpenSSL шифрует соединение по TLS 1.2, но проект
> пока не подключает хранилище доверенных корневых сертификатов и не проверяет
> имя сервера. Поэтому HTTPS в этой версии не защищает от активной подмены
> сервера. Не передавайте через встроенную загрузку чувствительные учётные
> данные и не полагайтесь на неё в недоверенной сети. Полное исправление требует
> перехода на системный TLS Windows либо поставки и регулярного обновления CA
> bundle с проверкой имени узла.

Если у вас уже есть доверенная совместимая пара DLL, скрипт может проверить её
архитектуру и скопировать без перезаписи:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-runtime.ps1 -Platform Win32 -SqliteDll "C:\Runtime\x86\sqlite3.dll" -OpenSslDirectory "C:\Runtime\x86\openssl" -Copy
```

## 5. Необязательный FastMM5

FastMM5 может быть полезен разработчику для диагностики памяти, но он не нужен
обычному пользователю и намеренно не включён в репозиторий.

Чтобы включить его вручную:

1. Получите FastMM5 из доверенного источника и отдельно ознакомьтесь с его
   лицензией.
2. В **Project Options → Delphi Compiler → Search path** добавьте папку, где
   находится `FastMM5.pas`.
3. В **Conditional defines** добавьте `USE_FASTMM5` для нужной конфигурации и
   платформы.
4. Выполните полный **Build**.

Модуль FastMM5 условно подключён первым в `uses`, как и требуется менеджеру
памяти. Без `USE_FASTMM5` проект не ищет этот модуль.

## 6. Командная сборка — только для подходящей лицензии

Delphi Community Edition не разрешает командную компиляцию. `dcc32`, `dcc64`
или MSBuild выводят сообщение `This version of the product does not support
command line compiling`. Некоторые версии при этом могут вернуть код `0`, даже
не создав `exe`, поэтому одного кода возврата недостаточно.

Если ваша коммерческая лицензия Delphi разрешает CLI, откройте поставляемую с
нужной версией Delphi командную строку RAD Studio, перейдите в корень репозитория
и выполните, например:

```powershell
msbuild Program\MyhomeLib.dproj /t:Build /p:Config=Release /p:Platform=Win32
msbuild Program\MyhomeLib.dproj /t:Build /p:Config=Release /p:Platform=Win64
```

После команды обязательно проверьте, что соответствующий `exe` существует,
имеет ненулевой размер и был обновлён текущей сборкой.

## 7. Запуск

1. Перейдите в `Program\Out\Bin` или `Program\Out\Bin64`.
2. Убедитесь, что рядом лежит проверенная `sqlite3.dll`.
3. Запустите `MyHomeLib.exe`.

Пользовательские настройки и база по умолчанию создаются в
`%APPDATA%\MyHomeLib`. Для переносного режима приложение поддерживает маркер
`uselocaldata` рядом с `exe`, но тогда папка приложения должна быть доступна для
записи; не используйте этот режим внутри `Program Files`.

## 8. Установщик

[Inno Setup](https://jrsoftware.org/isinfo.php) — необязательный следующий шаг.
Текущие сценарии в `Installer`
ссылаются на дополнительные каталоги `Common`, `x86` и `x64`, которых нет в
чистом репозитории. В них исторически находились SQLite/OpenSSL, справка,
списки жанров, AlReader и конвертеры. Поэтому установщик нельзя считать
воспроизводимым, пока эти файлы не получены легально, не проверены и не разложены
по ожидаемой структуре.

Для собственной сборки безопаснее сначала распространять проверенную папку
`exe + sqlite3.dll` (и необходимые вам данные) как ZIP. Если всё же нужен
инсталлятор, установите актуальный Inno Setup, подготовьте payload отдельно, проверьте
лицензии каждого стороннего файла и только затем компилируйте соответствующий
`.iss`: обычный для Win32 или `_x64` для Win64.

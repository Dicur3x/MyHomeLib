# Изолированные проверки коллекций

Дополнительно с 8 октября: `book-gallery` проверяет ленивую загрузку FB2/EPUB,
WebP по сигнатуре, изоляцию повреждённых картинок, отмену старой книги,
очистку памяти, листание и сохранённые размеры/положение крупного окна.
`column-filters` проверяет несколько условий вместе, плоский/сгруппированный
вид, пустой результат, сброс, отметку/выделение только подходящих книг.
Интерактивный стенд без личной библиотеки:
`gallery_preview_probe.js <runtime> <CollectionViewsTest.exe> [book-gallery|column-filters]`.

Проекты `GenreRegistryTest.dproj`, `MetabibImportTest.dproj` находятся в
`tools/metabib/tests`, проект `CollectionViewsTest.dproj` — в этой папке.
Все три собираются через IDE Delphi в Win64 и Win32. Открывать через
`C:\Users\cloud\HomeLibRu-build`, чтобы не создавать пустые RES из пути с `.codex`.
Выходные EXE: `Out/<Platform>`, отдельные DCU не попадают в runtime программы.
Assertions, range/overflow checking включены. Явный тестовый манифест
`asInvoker` исключает запрос повышенных прав для Win32.

Запускать только Node-обёрткой; её аргументы — runtime соответствующей
разрядности и три свежих тестовых EXE в указанном порядке:

```text
node tools/ui/tests/native_collection_tests.js <runtime-dir> <GenreRegistryTest.exe> <MetabibImportTest.exe> <CollectionViewsTest.exe>
```

Runner проверяет архитектуры PE, создаёт новую временную папку для каждого
сценария и копирует только тестовый EXE, разрешённые DLL (включая приватный
декодер `tools/webp/libwebp.dll`), значки и списки
жанров. `Data`, INI, presets и пользовательские архивы не копируются. Проверка
обновлений и OPDS выключены; сценарии онлайн-книг используют только отдельный
HTTP-сервер Node на `127.0.0.1`, без LAN и системного прокси.
Локальные маркеры `uselocaldata`/`uselocaltemp`
и отдельный проверяемый маркер не позволяют тестам открыть обычный профиль.
Без этих маркеров нативные EXE завершаются до создания DMUser или главной формы.
Тесты создают собственные небольшие коллекции; MCP fixture имеет другой
состав групп и не заменяет данные этих проверок.

Проверяются сохранение/откат/перечитывание реестра жанров, настоящий импорт
curated metabib с конфликтующим источником и потерей транзакции, языковые
фильтры и выбор книг при переключении коллекций, отложенные вкладки,
добавление в ещё не открытую группу, ссылка на жанр и сохранение жанров
источника при смене языка. Для верхнего жанра отдельно проверяется пустой
список до «Показать» и восстановление сохранённого языка при первом запросе.
Отдельный сценарий проверяет отложенную издательскую вкладку, сохранённые
язык/книгу и независимость от авторской вкладки. Настоящий INPX importer
проходит маленький combined каталог с совпадающими числовыми IDs и тремя
сериями, затем полный переимпорт одиночным original INPX с восстановлением
оценки, прогресса и группы. Через production book stream проверяются PNG
по умолчанию и точные исходные WebP/FB2 байты при сохранении оригинала.
Настоящий поток экспорта проверяет подготовку файла для скрипта без запуска
скриптов: архив распаковывается, выбранная политика PNG/оригинала применяется,
а архив остаётся неизменным. Отдельный FB2 с расширением в верхнем регистре
проходит обычный экспорт и подготовку для скрипта; неизменённые обычные FB2
сохраняют исходный путь. Две конвертируемые книги одинакового названия
обрабатываются одним пакетом; возвращённый файл первой книги должен сохранить
её текст и после подготовки второй, без перезаписи исходников.
Издательская вкладка учитывается как отдельная физическая вкладка; тесты
не полагаются на прежние порядковые PageIndex.

Меню столбцов проверяется отдельно: 13 колонок сохраняют ID из DFM, а
разделитель и стандартное расположение не становятся колонками. Сценарий
`reader-compatibility` вызывает настоящий `ReadBookExecute` с самим тестовым
EXE в роли короткой читалки-пробы. Дочерний процесс проверяет временные
маркеры, записывает только полученный путь внутри своей папки и завершается
до создания приложения и DMUser. Проверяются исходный путь обычного FB2,
PNG-копия книги с WebP, отдельный кэш для режима конвертации и неизменность
исходника. Установленные читалки и пользовательские настройки не используются.

Сценарий `online-download` создаёт настоящую онлайн FB2-коллекцию. Главное окно
вызывает `ReadBookExecute`, а затем настоящие добавление в очередь и запуск
менеджера загрузки. HTTP отдаёт ZIP с именем члена, отличающимся от имени INPX,
и встроенной WebP-обложкой. Проверяются обновление локального статуса в БД и
дереве, обложка в панели главной формы, повторное чтение, экспорт PNG/текста и
точная сохранность скачанного ZIP. Завершённая очередь запускается ещё раз для
другой удалённой книги. Runner требует ровно три запроса: повторное
чтение не должно снова скачивать книгу. `online-plain` отдельно проверяет
условный вариант онлайн-книги с путём отдельного FB2: скачивание должно
предшествовать открытию потока для конвертации. Это отдельный сценарий,
не доказательство причины сбоя обычного каталога Флибусты.

Для проверки только новых онлайн-сценариев добавить `--online-only` к команде
выше. `--online-archive-only` запускает только стандартный ZIP-сценарий,
чтобы сравнить исходное поведение до исправления. `--online-plain-only` запускает
только условный вариант отдельного FB2. Эти режимы не запускают
реестр/импорт и старые восемь UI-сценариев. Полный запуск также требует две
новые регрессии импортера: неизменённый одиночный онлайн INPX и отказ от
смешанного онлайн INPX без изменения существующих данных.

Временный ignored `tools/validation/Out/HomeLibValidation.groupproj`
объединяет основную программу, MCP и тесты. Это средство локальной сборки,
с абсолютными путями junction, его не коммитить. Перед открытием убедиться,
что все перечисленные DPROJ существуют. Сборка группы не запускает EXE.
6 октября 2026 года на финальных сборках pre5.09 / 2.7.0.1076 полный runner
прошёл в Win32 и Win64: реестр жанров, 11 групп импортера, восемь прежних
UI-сценариев и два новых онлайн-сценария. В ZIP-сценарии прошли прямое чтение,
настоящая очередь, повторный запуск очереди для другой книги и экспорт;
зафиксированы ровно три HTTP-запроса. Отдельный онлайн FB2 сначала скачивается,
затем передаётся читалке с выбранной конвертацией. Все временные данные удалены.

До производственных исправлений изолированный Win32-тест pre5.08 подтвердил
успешное прямое чтение стандартного онлайн ZIP, затем воспроизвёл исключение
`EThread` при запуске очереди. Условный отдельный онлайн FB2 воспроизвёл
`EBookNotFound` до HTTP-запроса. Эти результаты различают два исправленных
пути и не доказывают причину любого сетевого сбоя Флибусты.

Сценарии `read-folder-cleanup` и `temp-exit-cleanup` проверяют настоящую
команду очистки и разрушение главной формы: удаление копий WebP → PNG,
повторную очистку занятого файла после освобождения, сохранность исходной
книги, постоянной папки при выходе и посторонних подпапок. Ссылка/junction
вместо кэша не должна затронуть целевую папку. Все эти папки создаются
runner-ом только в его отдельном временном профиле. Полный запуск включает
10 локальных сценариев главной формы и 2 онлайн-сценария.

## Ссылки карточки и история обновлений

`publisher-links` проверяет плоский список издательских серий после отмены
группировки: старые свойства игнорируются, одна серия нескольких жанров
остаётся одной строкой. Проверяются сохранение текущей карточки и выбранной
книги/номера при переходах на авторскую серию, издательскую серию и жанр.

`program-update-ui` использует настоящую форму и редакторы: крупные жирные
заголовки с датами, вложенные Markdown/SQLite HTML списки и подзаголовки,
Unicode/RTF экранирование для приложения и всех компонентов. Новый выпуск
раскрыт, прежние свёрнуты; щелчок раскрывает/сворачивает их независимо.
Проверяется история установленной версии при новом обновлении, неверные
даты не выдумываются. Существующие проверки интервала/ручных результатов
и отсутствия скачивания без щелчка сохранены.

Дополнительно проверяются изменяемые размеры окна и большая область чтения,
полная высота длинного changelog без внутренней полосы прокрутки,
WM_MOUSEWHEEL над новым и прежним выпуском, Ctrl + колёсико и масштаб,
сохранение раскрытия/редактора при повторном одинаковом тексте.
Изменённые размеры окна и масштаб 140% записываются на диск; новый
экземпляр формы должен восстановить оба размера и масштаб.
Кэш приложения и компонентов читается новым окном без сети; частичная
ошибка сохраняет историю, но не оживляет прежние сведения для скачивания.
Пустое тело release JSON обозначается как отсутствие текста у автора.

Отдельно `Program/Tests/program_updates_tests.js <ProgramUpdatesTest.exe>`
использует loopback HTTP: ETag/304 с двумя загрузками тела в четырёх
проверках, новая версия после изменения ETag, ошибка при сохранённом кэше,
Last-Modified/304. С прежними сценариями всего 87 проверок на архитектуру.

Полный сценарий с отдельным loopback ZIP:

```text
node Program/Tests/program_update_popup_tests.js <CollectionViewsTest.exe> <ProgramUpdateInstallerTest.exe> <runtime-dir> <python.exe>
```

Он проверяет скачивание/байты, сохранность журнала, «Позже», восстановление
готового пакета, закрытие главной формы, замену и точные аргументы перезапуска.

`first-run` и `first-run-cancel` запускают главное окно с действительно пустой
системной базой: проверяют видимый мастер, создание без импорта и отмену.
Для этих двух сценариев runner не задаёт Windows скрытый первый показ окна;
иначе проверялось бы скрытие, навязанное самим запуском теста.

## Проверки pre5.13

Все Delphi-проекты собираются через RAD Studio GUI, Release, для Win32 и Win64.
`BuiltinReaderTest.dproj` проверяет документ, окно, поиск, настройки, PDF и
визуальные форматы. `Round2Probe.dproj` проверяет архивы, подготовку форматов,
выбор читалки, кэш, окно источников и повреждённые настройки столбцов.
Запуски используют отдельные профили в TEMP с отключённым OPDS.

`builtin_reader_tests.py <runtime> <BuiltinReaderTest.exe> <pdfium.dll>` создаёт
синтетические документы. `--case` выбирает отдельную проверку, `--keep` оставляет
артефакты. Длинные прогоны проверяют GDI/USER после прогрева. Отдельные проекты
Benchmark, PDFBenchmark и Audit измеряют подготовку и повторные открытия.

Режимы `raster-reader` и `release-pagination` также проверяют выбранные настоящие
DjVu/CBR/CBZ/TIFF. Они требуют `--books-root <папка-архивов>` и
`--raster-catalog <inventory.json>`. JSON содержит список, последний элемент
которого имеет `samples`: записи с `ext`, `folder`, `file_name`, `book_id`.
Для `real-formats` вместо этого нужен `--headers-json <headers.json>`: список
записей `status`, `signature`, `catalog_ext`, `archive`, `actual_member`, `book_id`.
Инвентаризации и настоящие книги предоставляются отдельно и не публикуются.
Исходные архивы открываются только для чтения; CRC и неизменность проверяются.
`BuiltinReaderLibraryProbe` с `builtin_reader_library_probe.py` проверяет
выбранные LightLib FB2 с оригинальными WebP. Его список примеров указан в коде;
папка архивов передаётся аргументом, без привязки к диску конкретной машины.

`djvu_worker_tests.py <tools/djvu> <многостраничный-DjVu>` сравнивает пиксели с
официальным ddjvu, проверяет Unicode, границы, неверную страницу, повреждённый
файл и 12 прерываний декодера. Требуется Pillow. Сам помощник собирается через
RAD Studio из `Utils/HomeLibDjvu/HomeLibDjvu.dproj`, Release/Win32.

`native_collection_tests.js` и стандартный `CollectionViewsTest.dproj` включают:

- `--views-mode=builtin-reader`: флажок открытия по умолчанию, блокировку
  внешних назначений, сохранение путей и явную внешнюю команду;
- `--views-mode=program-update-ui`: DjVu/7-Zip, сайт автора, выбор компонента,
  совместную установку и исключение компонентов с одной проверкой;
- `--views-mode=audit-new --audit-case=<case>`: `filters`, `archives`, `images`,
  `orphan`, `active-pending`, `nested`, `collision`, `failure`, `return`,
  `performance`, `legacy`. Для `inflight` и `source-inflight` дополнительно
  передаётся `--amber-archive=<ZIP LightLib>`, только для чтения.

Проверки требуют соответствующего поведения: е/ё и регистр, несколько значений,
точное PDF/FBD по UTF-8 пути, отказ от чужого FBD, исходные изображения,
границы декодирования, отмена с сохранением таблицы, ошибка переноса с повтором,
A→B→A, активная распаковка, отключение источника и сохранность чужих файлов.
Проверяется точный Source ID SQLite 3.54.0, FTS5 Unicode MATCH и integrity_check.

Результаты и границы: [отчёт выпуска](../../../docs/RELEASE_VALIDATION_2.7.0_pre5.13.md).
